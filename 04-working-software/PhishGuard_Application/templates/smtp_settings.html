1. Server and sender

Provider presets fill in host, port, and encryption. Choose Custom for an organizational relay.

Preset providers apply their approved host after saving.

Campaigns use this domain to generate randomized simulation identities such as account-a1b2c3@{{ smtp.training_domain }}. The actual SMTP From address remains the approved sender above.

2. Recipient-accessible training site

Live email requires public HTTPS. Replace the packaged https://training.example.org placeholder with the deployed site. A local 127.0.0.1 or localhost address works only for preview testing.

3. Gmail simulation recipients

When selected, preview wildcard mode is replaced with the explicit gmail.com domain while retaining any other specifically authorized domains. Remove the domain later from Domain mode when the simulation ends.

4. Authentication

Use a dedicated training mailbox and an app password or approved relay credential. The password is never displayed or written to the audit log.

5. Verify connection

Save the settings first. A connection test signs in without sending mail. To confirm delivery, enter one address from a specifically authorized client domain.

Gmail support: choose Google Workspace / Gmail when the approved sender mailbox uses Google's SMTP service. To send an authorized simulation to personal Gmail recipients, also enable the explicit gmail.com recipient-domain option above, save, and verify the connection with an approved test address.
